## T00 项目骨架

**目标**：一个能运行、能测试、能打包的空项目。

**范围**：项目根目录配置文件、`src/` 空目录结构、`tests/`、`tools/`、`docs/PROGRESS.md`、`docs/DECISIONS.md`。

**要做的事**
1. 用 Vite 建立 React + TypeScript 项目，`tsconfig` 开启 strict。
2. 安装 Vitest、tsx、ESLint（含 TypeScript 支持）、Phaser、React。
3. 按 `03_TECH_SPEC.md` 第 2 节建立目录，每个目录放一个占位 `index.ts`。
4. 配置 ESLint `no-restricted-imports`：`src/core|sim|game|save` 禁止引用 react、phaser、DOM 全局对象。
5. `package.json` 脚本：`dev`、`build`、`test`、`lint`、`sim`（先放占位脚本，打印 "sim not ready"）。
6. 首页显示"电竞帝国 · P0 开发中"。
7. 一个示例测试，确保 `npm test` 跑通。
8. 初始化 git，提交 `T00: project skeleton`。
9. 在 DECISIONS.md 记录 Node、React、Phaser、Vite 实际版本号。

**不做**：任何游戏逻辑。

**验收**
- `npm install`、`npm run dev`（浏览器能看到标题）、`npm test`、`npm run lint`、`npm run build` 全部成功。
- 在 `src/sim/index.ts` 里写一行 `import 'react'`，`npm run lint` 会报错（验证后删掉）。

**回退**：删除整个项目重建，代价很小。

## T01 核心类型、随机数、示例数据

**目标**：所有后续任务共用的"地基"，完成后冻结接口。

**范围**：`src/core/*`、`src/data/*`、`tests/core/*`。

**要做的事**
1. 按技术规范第 4 节实现 `types.ts`（可增字段，不能少）。
2. 实现 `rng.ts`（第 3 节），包括 `fork` 和 `state`。
3. 实现 `config.ts`：加载并校验全部 JSON，返回 `GameData` 对象。
4. 编写数据：
   - `heroes.json`：10 个原创英雄，五类各 2 个，每个 1 个技能，名字和技能名原创、有中文味道或架空风格均可，**不得与现有游戏重名或明显模仿**。
   - `players.json`：30 名原创选手（虚构游戏 ID，如"北辰""Kuro_7"之类的风格），五个位置各 6 人，能力 40–80 分布，工资与能力正相关但有性价比差异（有便宜好用的，也有贵而一般的）。
   - `clubs.json`：5 支 AI 俱乐部，原创队名，实力从弱到强，风格各异，每支 5–6 名专属选手。
   - `economy.json`、`match.json`：按 GDD 和技术规范填〔P0默认〕值，`match.json` 先放时间、能力系数、战术修正，地图部分 T02 补。
5. 测试：RNG 同种子序列一致、`fork` 互不影响；数据校验能抓出缺字段、重复 ID、阵容位置重复等错误。

**不做**：任何比赛和经营逻辑。

**验收**
- `npm test` 通过。
- 测试覆盖：同 seed 生成 1 万个数完全一致；改一个字段错误的 JSON 会被校验报出具体位置。
- 汇报中附上 10 个英雄的名字、定位和技能一句话说明，便于门哥过目。

**回退**：数据文件可随时改；类型如需大改，在 T02 开始前完成。

## T02 地图与移动

**目标**：单位能在节点图上按最短路移动。

**范围**：`src/sim/map.ts`、`src/sim/units.ts`（移动部分）、`src/data/match.json`（地图部分）、`tests/sim/*`。

**要做的事**
1. 在 `match.json` 中定义地图节点与连线（技术规范 5.3）。
2. 实现最短路（可预计算全对全路径表）。
3. 单位位置 `{from, to, progress}`，按移动速度每 tick 推进；到达后继续沿路径走。
4. 函数：给出单位当前坐标（插值）、两单位距离。
5. 兵团生成与沿路行进（还不需要战斗）。
6. 一个调试脚本：输出某单位从蓝基地走到红基地经过的节点和耗时。

**不做**：战斗、AI。

**验收**
- 测试：地图连通；任意两节点有路径；同输入移动结果一致；兵团从基地出发按预期时间到达路中点。
- 汇报附上地图节点示意（ASCII 草图或节点坐标表即可）。

**回退**：地图是数据，改 JSON 即可。

## T03 战斗、技能、金币等级

**目标**：英雄、兵团、塔、基地之间能互相攻击，有死亡复活、金币和等级。

**范围**：`src/sim/combat.ts`、`src/sim/units.ts`、`src/data/match.json`、`src/data/heroes.json`（只调数值）、`tests/sim/*`。

**要做的事**
1. 普通攻击：范围内按攻击间隔造成伤害，护甲减伤（公式数据化）。
2. 技能：冷却、范围、六种效果（伤害、眩晕、护盾、治疗、位移、减速）。
3. 死亡与复活，复活回到己方基地。
4. 塔的目标优先级、塔的拆除顺序规则、基地可被攻击的条件（技术规范 5.4）。
5. 金币、经验、等级、金币转属性（5.5）。
6. 中立资源的刷新、击杀和增益。
7. 选手能力系数（5.6）在这里生效：操作、熟练度、状态、位置。
8. 测试用的"脚本对战"：手动把两个英雄放在同一节点让它们打，验证伤害符合公式。

**不做**：AI 决策（本任务里单位可以用最简单的"沿路前进，见敌就打"行为测试）。

**验收**
- 测试：伤害公式；技能冷却；眩晕期间不能行动；死亡与复活时间；一塔未拆不能打二塔；熟练度和位置系数生效。
- 用"沿路前进见敌就打"的傻瓜 AI 跑 100 场，比赛都能结束（有一方基地被拆或触发超时机制）。

**回退**：数值在 JSON 里，公式集中在 `combat.ts`。

## T04 角色 AI 与战术

**目标**：英雄能像在打比赛：对线、发育、抓人、团战、推塔、撤退；四种战术产生不同行为。

**范围**：`src/sim/ai.ts`、`src/sim/tactics.ts`、`src/data/match.json`（AI 与战术参数）、`tests/sim/*`。

**要做的事**
1. 按技术规范 5.7 实现效用值决策。
2. 战术修正表数据化。
3. 意识影响决策频率和随机扰动；配合影响集合到场的时间差；心态影响落后时的发挥。
4. 团战识别：一定范围内双方 ≥3 人交战，写 `TEAMFIGHT_START/END` 事件。
5. 决策事件写入日志，带 `reason`。
6. 防拖延机制（5.8）。

**不做**：战报文字、批量统计报告。

**验收**
- 测试：
  - EARLY_AGGRO 的队伍在前 12 分钟的 GANK 次数平均明显多于 STEADY_MACRO（跑 200 场比较平均值）。
  - SPLIT_PUSH 的队伍有分带事件；TEAMFIGHT_PUSH 的队伍 12 分钟后团战次数更多。
  - 低血量英雄会撤退；意识 90 的英雄被抓死次数少于意识 40 的英雄（统计意义上）。
  - 200 场中没有一场超过 45 分钟。
- 汇报附上一场比赛的事件日志前 50 条（中文可读化）。

**回退**：AI 参数在 JSON，行为逻辑集中在 `ai.ts`。

## T05 胜负、事件日志、战报

**目标**：完整的 `runMatch`，输出结果、统计、事件日志和中文战报。

**范围**：`src/sim/engine.ts`、`src/sim/events.ts`、`src/sim/report.ts`、`tests/sim/*`。

**要做的事**
1. 按技术规范 5.1 实现对外接口，`runMatch` = 反复 `step` 到结束。
2. `getSnapshot` 输出画面所需的全部信息（单位位置、血量、技能释放、最近事件）。
3. `finalize`：统计 KDA、金币、伤害、评分、MVP、金币差时间线、checksum。
4. `buildReport`：生成一句话结论 + 3 条关键原因（每条带 eventRefs）+ 评分。原因优先关联赛前选择。
5. 一个命令 `npm run sim -- --one --seed 42`：跑一场，打印中文战报和关键事件。

**不做**：批量统计。

**验收**
- 测试：同 seed 两次 `runMatch` 的 checksum 相同；"逐 tick step 到结束"与 `runMatch` 结果相同；每条关键原因的 eventRefs 都指向真实存在的事件。
- 汇报附上 3 场不同 seed 的中文战报原文。

**回退**：战报规则集中在 `report.ts`，可单独重写。

## T06 批量模拟与平衡报告

**目标**：一条命令跑上千场，自动检查 GDD 第 16.1 节 G1–G9 指标，并调整数值直到通过。

**范围**：`tools/sim-cli.ts`、`src/data/*.json`（只调数值）、`src/sim/*`（只修 bug 和必要的公式调整）、`docs/reports/`（报告输出）。

**要做的事**
1. `npm run sim -- --n 1000`：跑完所有 G1–G9 场景，输出一份 Markdown 报告到 `docs/reports/balance-YYYYMMDD.md`，内容包括：
   - 每项指标的实际数值、标准、是否通过。
   - 四种战术对阵胜率矩阵（4×4 表）。
   - 比赛时长分布（中位数、90%、99%、最长）。
   - 10 个英雄的出场胜率。
   - 跑完耗时。
2. 调数值使全部指标通过。**只能改数值和必要公式，不能为了过关写针对测试的特殊逻辑**（例如检测到测试场景就改变行为）。
3. 汇报中用大白话解释：哪些选择对胜负影响大、影响多少。

**不做**：经营、界面、画面。

**验收**
- G1–G9 全部通过，报告文件存在。
- 如果某项多次调整仍不能通过，停下汇报：现状数值、你判断的原因、三个可选办法（放宽标准 / 改规则 / 重写某部分）和各自代价。

**回退**：数值有 git 历史，可回到任意一次提交。

## T07 迷你经营逻辑

**目标**：P0 的经营闭环（纯逻辑，无界面）。

**范围**：`src/game/*`、`src/data/economy.json`、`tests/game/*`。

**要做的事**
1. `GameState`：俱乐部名、颜色、资金、本队选手、市场选手、AI 俱乐部、赛程、已赛结果、当前周、积分榜、历史战报、随机数状态。
2. 新游戏：`newGame(name, color, seed, data)`。
3. 市场：列出自由选手；签约（扣签约费，选手入队）；解约（付违约金，回到市场）；人数 5–8；资金不足时拒绝并给出原因。
4. 阵容：设置 5 个位置的首发、英雄、战术，校验合法性；`recommendLineup()` 一键推荐（按位置和熟练度选最优）。
5. 赛程：6 队双循环共 10 轮，用 seed 生成；AI 对 AI 的比赛也真实模拟（可调用 `runMatch`）。
6. `advanceWeek()`：结算周薪和赞助 → 进行本周所有比赛 → 发奖金 → 更新积分榜 → 返回本周结果。**玩家比赛的 `MatchInput` 需要单独暴露，供画面层先观看再结算**（见下方接口）。
7. 财务：每周收支明细、"按当前开销可撑几周"、低资金警告。
8. 选手状态 form 每周小幅随机变化。

建议接口：
```ts
prepareWeek(state): { playerMatch: MatchInput | null }   // 画面层拿去播放
commitWeek(state, playerMatchResult?: MatchResult): WeekSummary // 结算；不传则内部自己跑
```
`commitWeek` 内部如果自己跑，必须得到与画面层播放完全相同的结果（同 seed 同输入）。

**不做**：界面、存档、训练、转会谈判、合同到期。

**验收**
- 测试：资金守恒（起始资金 + 所有收入 − 所有支出 = 当前资金）；不能超编或少于 5 人；同 seed 赛程相同；10 轮后积分榜总场次正确。
- 模拟测试：用"一键推荐 + 签 5 个性价比选手"的策略自动玩 10 轮，跑 100 个不同 seed，资金结束值在起始资金的 60%–150% 之间的比例 ≥80%。不满足则调 `economy.json` 并说明。

**回退**：经营逻辑独立于引擎和界面。

## T09 管理界面

**回退**：界面只读写经营状态，可整体替换。

## T10 比赛画面

**目标**：俯视像素小人比赛，看得懂、可暂停、可变速、可跳过。

**范围**：`src/render/*`、`src/ui/` 中比赛页相关文件、`public/` 或 `src/render/assets/`（占位美术）。

**要做的事**
1. Phaser 场景：画地图（路、野区、河道、塔、基地），用 `getSnapshot` 每 tick 更新，两 tick 之间插值。
2. 单位：英雄用 16×16 或 24×24 像素小人（用代码生成几何图形或简单像素图，按队伍着色，头顶显示血条和选手名），兵团用小方块群，塔和基地显示血条。
3. 表现：普通攻击用短线或小弹道；技能用醒目的圆圈/闪光；死亡淡出；击杀、拆塔、拿资源时画面中央或侧边弹出中文提示。
4. 顶部比分条：时间、双方击杀、金币差、塔数。侧边事件滚动列表。
5. 控制：暂停、1×/2×/4×、跳过。跳过 = 不渲染直接 step 到结束。
6. 比赛结束 → 进入战报页 → 调用 `commitWeek(state, result)` 结算。
7. 1 倍速整场观看约 2–3 分钟（参数在 `match.json`）。

**不做**：音效、高级特效、镜头跟随（可选，不强求）。

**验收**
