# P1 开发任务书：单个 MOBA 分部可玩

> 2026-10-23 · GATE-2 通过后编写 · 依据 GDD 第 15 节 P1
> 目标：从开局玩完**一个完整赛季**（休赛期 → 常规赛 → 季后赛 → 休赛期），财务与排名形成闭环，重新加载后数据一致；并能接着打第二个赛季。
> 原则不变：一次一个任务、每个任务有测试和汇报、关卡停下等门哥。P1 不做 P2 内容（性格、默契、设施、职业生涯、退役、名人堂）。

## T12 状态模型扩展与存档 v2

**目标**：P1 需要的所有数据先就位，旧存档能升级。
**范围**：`src/core/types.ts`（追加字段）、`src/core/config.ts`、`src/data/*.json`、`src/game/state.ts`、`src/save/*`、`tests/*`。
**要做的事**
1. 选手：合同（到期赛季、周薪、签约年限）、潜力（隐藏，0–100）、疲劳 0–100、士气 0–100、身价、历史统计（场次、胜场、KDA）。
2. 俱乐部：声望 0–100、赞助合同列表、预算；AI 俱乐部也有资金。
3. 游戏状态：日历（赛季号、阶段、第几天）、收件箱消息、赛季历史（往届排名、冠军）。
4. 配置文件新增 `season.json`（赛季结构、时间流速）和 `growth.json`（成长参数），都按上表默认值。
5. 存档 v2 + 真实的 v1→v2 升级：P0 存档读进来后自动补齐新字段，能继续玩。
**不做**：任何新玩法逻辑。
**验收**：P0 的全部测试继续通过；用 P0 的真实存档升级后能继续打完赛季；新字段都有校验。

## T13 日历与正式赛季

**目标**：时间按天流动，一个赛季完整走完并进入下一个赛季。
**范围**：`src/game/calendar.ts`、`src/game/season.ts`、`src/game/*`、`tests/game/*`。
**要做的事**
1. 日历：`tick(days)` 推进；每天结算当天事件（训练、比赛、发薪日、合同到期）。
2. 阶段：休赛期（转会窗口开）→ 常规赛（每周 1 轮）→ 季后赛（前 4 名：1 对 4、2 对 3，胜者决赛）→ 颁奖 → 新赛季。
3. 自动暂停事件表（比赛日、报价、合同到期提醒、资金预警），数据化。
4. 新赛季：重排赛程、重置积分、选手年龄 +1、写入赛季历史。
5. 保留"直接跳到下一场比赛"的快捷方式。
**不做**：训练效果、转会（只留接口）。
**验收**：用自动策略连续跑 3 个赛季不报错；每个赛季积分、季后赛对阵、冠军记录正确；存档读档后日历一致；同 seed 结果完全相同。

## T14 训练与成长、状态

**目标**：选手会成长、会累、会有情绪，并且这些会影响比赛。
**范围**：`src/game/training.ts`、`src/sim/units.ts`（只接入系数）、`src/data/growth.json`、`tests/*`。
**要做的事**
1. 每周训练计划：全队选一个侧重（操作 / 意识 / 配合 / 心态 / 英雄熟练度 / 休息）。
2. 成长：受潜力、年龄（年轻长得快、27 岁后缓慢下滑）、上场经验、训练侧重影响；隐藏潜力决定上限。
3. 疲劳：比赛和高强度训练增加，休息恢复；疲劳高时发挥下降。
4. 士气：输赢、上场时间、合同满意度影响；士气影响状态（form）。
5. 比赛引擎接入疲劳和士气系数（数据化）；G1–G9 必须继续通过。
**不做**：性格词条、默契（P2）。
**验收**：批量测试——高潜力年轻选手一个赛季平均成长明显高于老将；连续不休息的队伍胜率下降；G1–G9 全过。

## T15 合同与转会

**目标**：选手有合同、会到期、能买卖。
**范围**：`src/game/contracts.ts`、`src/game/transfers.ts`、`tests/*`。
**要做的事**
1. 身价公式（能力、年龄、潜力、近期表现），数据化。
2. 续约：合同最后一个赛季可谈；选手按身价和士气开价，玩家可接受 / 拒绝 / 还价一次。
3. 转会：休赛期可向其他俱乐部报价买人；AI 按自己的需求接受或拒绝；AI 也会向玩家报价买人。
4. 合同到期未续约 → 成为自由球员。
5. 解约违约金按剩余合同计算。
**不做**：经纪人、球探误差、租借。
**验收**：资金守恒（转会费一进一出）；合同到期的选手正确离队；AI 不会签超出预算的人；同 seed 结果相同。

## T16 完整财务

**目标**：钱有多种来源和去处，能看懂、能挽救。
**范围**：`src/game/finance.ts`、`src/data/economy.json`、`tests/*`。
**要做的事**
1. 收入：赞助合同（按声望分 3 档，可选签哪家、签多久）、联赛分成、比赛奖金、季后赛奖金、周边收入（随声望和战绩变化）、卖人。
2. 支出：工资、签约费、转会费、违约金、训练开销。
3. 声望：战绩、季后赛、冠军提升，连败下降。
4. 挽救：资金低于预警线时提示可以卖人、接低档赞助；资金为负时禁止签人和买人（P1 仍不做破产，GDD"禁止隐形破产"）。
5. 现金流预测：未来 4 周的预计收支。
**验收**：资金守恒；经济校准——用"普通经营"策略跑 100 个赛季，资金结束值在起始的 60%–150% 的比例 ≥80%；豪门策略不会无限亏也不会无限赚。

## T17 AI 俱乐部运营

**目标**：AI 俱乐部像真的对手一样经营。
**范围**：`src/game/ai-clubs.ts`、`src/data/clubs.json`（风格参数）、`tests/*`。
**要做的事**
1. 每家 AI 有预算和经营风格（豪门、青训、稳健、激进、没落豪门）。
2. 会签自由球员、续约、卖人、按疲劳和状态轮换首发、选战术。
3. 和玩家遵守同样的规则（合同、预算、转会窗口），不凭空得钱。
**验收**：批量跑 20 个赛季，没有 AI 俱乐部人数不足或资金爆炸；强弱会随经营起伏（不是永远同一家夺冠）。

**验收**：浏览器自动操作打完一个完整赛季（含续约、买人、季后赛）无报错；手机宽度下所有页面可用。
