# T08 汇报：存档系统

**结论**：✅ 完成。存档带版本号，写到一半出错不会弄坏旧存档，坏存档会给出明确提示。

**做了什么**
- `src/save/save.ts`：存档的序列化、读取、校验、版本升级框架、安全写入、自动备份、导入导出用的纯函数。
- 存储方式通过 `StorageAdapter` 接口注入：网页里用浏览器本地存储，测试里用内存。存档模块本身不碰浏览器，也不读时钟（存档时间由界面层传入）。
- 安全写入：先写临时位置 → 读回来校验 → 把上一份好存档留作备份 → 再替换正式存档。
- 读档：主存档坏了就自动读备份，并说明原因；读档过程从不删除、覆盖任何东西。
- 导出文件名示例：`电竞帝国_门哥电竞_第3轮_20261022.json`。

**怎么验证的**
- `npm test`：通过 85 / 失败 0（本任务新增 12 个）
- `npm run lint`：0 个问题
- 验收逐条：
  - ✅ 存档 → 读档 → 继续玩 3 周，与不存档直接玩 3 周，结果完全一致
  - ✅ 写入正式存档时故意报错，原存档原封不动，仍能正常读取
  - ✅ 损坏的 JSON 返回"存档文件已损坏"，不会崩溃
  - ✅ 版本号更高的存档提示"存档版本过新，请更新游戏"
  - ✅ 用一个假的 v0 存档测试了版本升级框架：能从 v0 升级到 v1；缺少升级步骤时会说明

**发现并修复**：对手视角的经济曲线里出现过"负零"，存成 JSON 后会变成普通的 0，导致"存档前后状态不完全一致"。对游戏结果没有影响，已改掉。
