# T21 汇报：数据扩展与存档 v3

**结论**：✅ 完成。P2 要用的数据都已就位，旧存档能升级。这一步只放数据，玩法和画面都没变。

**做了什么**
- **选手**多了 4 项：
  - 性格（0–2 个）
  - 成长类型（早熟 / 正常 / 大器晚成）
  - 生涯记录：每个赛季的球队、场次、胜场、是否夺冠、赛季末能力
  - 是否退役
- **性格和成长类型怎么来**：按选手编号固定算出来，同一个选手每次开新档都一样。这样不占用游戏的随机数，比赛和赛季结果不受影响。
  - 新秀也一样有性格。
  - 大约 35% 没有性格、45% 有 1 个、20% 有 2 个。
  - 矛盾的性格不会同时出现，比如刻苦和懒散、大心脏和玻璃心、务实和爱钱。
- **俱乐部**多了 5 个房间的等级（训练室、休息室、办公室、分析室、直播间），现在都是 1 级。
- **游戏**多了 3 张空表，后面的任务会往里填：
  - 两两默契表（T25）
  - 名人堂（T27）
  - 历届 MVP（T27）
- **赛季结束时**，每个在队选手自动记一行生涯。
- **新配置文件**（数字都是〔待确认〕，后面的任务用到时再校准）：
  - `facilities.json`：5 个房间各 3 级的价格、每周维护费和效果。
  - `traits.json`：8 种性格，每种的说明和效果。比赛相关的效果最多 ±5%，超出会报错（D50）。
  - `growth.json`：三种成长类型的比例和年龄偏移（T23 用）。
- **存档 v3**：P1 存档读进来会自动补上这些字段，性格和新开档一样，接着玩。P0 存档也会一路升级到 v3。

**怎么验证的**
- `npm test`：通过 182 / 失败 0。本任务新增 9 个：
  - 同一个选手每次的性格都相同，所有人都有性格和成长类型。
  - 2000 个测试选手里，没有矛盾的性格组合，比例符合配置。
  - 新开档用掉的随机数和原来完全一样，只有排赛程用。
  - 数据检查：比赛效果超过 ±5% 的性格会报错；房间 1 级不免费或少了房间会报错。
  - 赛季结束每个在队选手都有一行生涯，场次、胜场和统计一致；自由球员没有。
  - 用真实的 P1 存档升级：性格和新开档一致；房间都是 1 级；能接着打完赛季；生涯记上了；能再存档。
  - 设施等级坏掉的存档会被拒绝，不会读进来。
- 真实的 P1 存档：用上一个版本（F1）的代码打完一个赛季再打一个月，存下来放在 `tests/save/fixtures/p1-save-v2.json`。
- `npm run lint`：0 个问题；`npm run build`：成功
- 比赛结果不变：40 场固定对局校验码与改前相同。
- 浏览器测试：手机两赛季（中途多次刷新，前后一致）、手机一个赛季都通过，0 个报错。
