## 开发阶段决定

（Agent 从 D11 开始追加）

- **D11** · 2026-10-22 · Claude Code · T00 实际版本（全部锁定精确版本）：Node 22.22.0（要求 ≥20.19，Vite 8 的最低要求）、React 19.3.1、Phaser 4.2.1、Vite 8.3.4、Vitest 5.0.5、TypeScript 6.0.3、ESLint 10.12.0、typescript-eslint 8.71.1、tsx 4.23.15。原因：选当时最新稳定大版本。TypeScript 用 6.0 而非 7.0，因为 typescript-eslint 目前只支持 <6.1。Vitest 用 5.0.5 而非 5.0.3，因为 5.0.3 触发 npm 10 的依赖解析崩溃（`edgesOut` 错误）。
- **D12** · 2026-10-22 · Claude Code · ESLint 对 `src/core|sim|game|save` 除禁止引用 react/phaser/ui/render 外，还禁止 `window`/`document`/`localStorage` 等浏览器全局对象，以及 `Math.random`、`Date.now`、`new Date()`，从工具层面保证确定性。
- **D13** · 2026-10-22 · Claude Code · `tsconfig` 额外开启 `noUncheckedIndexedAccess`（数组/对象取值可能为空时强制处理），减少模拟代码中的越界 bug。
- **D14** · 2026-10-22 · 门哥 · T01–T06 连续做，中途不停，到 GATE-1 再停下汇报。每个任务仍单独提交、单独写汇报（存放在 `docs/reports/Txx.md`）。取代 AGENTS.md 第 3.1 条"每个任务停下等确认"在 P0a 阶段的适用。
- **D15** · 2026-10-22 · Claude Code · 技能效果数值约定：DAMAGE/SHIELD/HEAL 的 value 是"施法者攻击力的倍数"；STUN/SLOW 是秒数；DASH 是位移距离。己方/自身目标技能附带的 STUN/SLOW/DAMAGE 作用于施法者周围 `areaRadius` 内的敌人。随机数选用 sfc32 + splitmix32 播种。地图坐标采用屏幕坐标（y 向下），红方节点是蓝方节点沿河道线 y=x 的镜像，保证两边地形完全对称。
- **D16** · 2026-10-22 · 门哥 · G9（性能）按"用模拟工具实际跑完 1000 场的时间"计算，工具默认用满全部 CPU 核心；单线程耗时同时写入报告供参考。
- **D17** · 2026-10-22 · Claude Code（待门哥在 GATE-1 确认）· 公式调整：战术除了改变 AI 决策权重，还带三个数据化参数——`powerCurve`（某时间段全队伤害倍率，即"前期强/后期强"）、`farmGold`（补兵/野怪收入倍率）、`siegeDamage`（打塔倍率）。原因：只靠决策权重时，四种战术要么一边倒、要么完全没差别，做不出 GDD 第 8 节写的强弱特点。现值：前期猛攻 14 分钟前伤害 ×1.08；稳健运营 18 分钟后伤害 ×1.10、收入 ×1.18；团战推进打塔 ×1.1、12 分钟前伤害 ×0.97；分带牵制打塔 ×1.25。
- **D18** · 2026-10-22 · Claude Code · 公式调整：英雄打塔和基地只造成 65% 伤害（`hero.structureDamage`），否则 5 人抱团 1 分钟内就能连拆两塔和基地。
- **D19** · 2026-10-22 · Claude Code · 选手能力系数下调（技术规范 5.6 写明"具体系数由 T06 调整"）：操作伤害 0.9+0.002×操作，技能命中 0.65+0.003×操作，补刀 0.8+0.004×操作，熟练度技能效果 0.875+0.0025×熟练度，冷却缩减 0.0015×熟练度，副位置 ×0.98，非擅长位置 ×0.95。原值下熟练度 90 对 40 胜率 84%、全队打错位置胜率 0.4%，太绝对。
- **D20** · 2026-10-22 · Claude Code · 英雄"擅长位置"收窄，每个位置只留真正合适的英雄（中路：星烛、霜笛；打野：夜枭、绯刃；上单：磐岳、铁棘、绯刃；射手：逐风、赤隼；辅助：霜笛、青萝、鸣钟）。选手对已不属于其位置的英雄的熟练度，平移到该位置的英雄上（熟练度数值不变）。原因：射手放中路、刺客放中路时胜率差到 93% 对 3%。
- **D21** · 2026-10-22 · Claude Code · 公平性修正：同一秒内的效果按"护盾→伤害→治疗→控制"固定顺序结算；中立资源和野怪的最后一击归本秒伤害更高的一方；AI 察觉抓人只读回合开始时的状态。修正前完全相同的两队，蓝方胜率会在 44%–56% 间随机偏移。
