## 给门哥看的（3 分钟读完）

### 这个包是什么
一整套"交给 AI 就能开工"的文件。Agent 打开文件夹后，先读 `AGENTS.md`，就知道按什么顺序做、每步做到什么程度、做完怎么向你汇报。

### 包里有什么

| 文件 | 作用 |
|---|---|
| `AGENTS.md` | Agent 的总规矩（Codex 会自动读它） |
| `CLAUDE.md` | Claude Code 的入口，内容指向 AGENTS.md |
| `docs/01_GDD.md` | 总策划案 V1.1（优化版） |
| `docs/02_P0_TASKS.md` | P0 任务书：T00–T11，一步一步做 |
| `docs/03_TECH_SPEC.md` | 技术规范：目录、接口、数据格式、比赛引擎设计 |
| `docs/04_MULTI_AGENT.md` | 多个 Agent 怎么分工、怎么不打架 |
| `docs/05_REPORT_TEMPLATE.md` | Agent 每做完一步给你的汇报格式 |
| `docs/PROGRESS.md` | 进度表（Agent 自己更新，你随时看） |
| `docs/DECISIONS.md` | 决策记录（谁定了什么、为什么） |

### 推荐用法（先说结论）

**一个 Agent 按顺序做，另一个负责审查。**比三个同时写代码稳得多。

- **Claude Code：主开发**，从 T00 做到 T11。
- **Codex：审查员**。每完成一个任务，让它检查有没有 bug、有没有违反规矩。
- **Grok Bot：策划审查**。它如果不能直接操作代码文件夹，就让它看 `PROGRESS.md` 和汇报，帮你判断"好不好玩、数值合不合理"。

三个 Agent 同时写代码也行，但需要用 git 合并各自的成果。你没有技术背景，合并出问题时会很难收拾。确实想并行，按 `docs/04_MULTI_AGENT.md` 的"方案 B"来，而且等 T00、T01 做完再分。

### 怎么开工（Claude Code）

1. 把压缩包解压到电脑上，比如 `D:\esports-empire`。
2. 在这个文件夹里打开终端：Windows 在文件夹地址栏输入 `cmd` 回车；Mac 右键选"新建位于文件夹位置的终端窗口"。
3. 输入 `claude` 回车。
4. 把下面这段话粘贴进去：

```
请先完整阅读 AGENTS.md，再按它要求的顺序阅读 docs 里的文件。
读完后用中文告诉我：你理解的项目目标、P0 要做什么、你准备先做哪个任务。
先不要写代码，等我回复"开始"。
```

5. 它复述得没问题，你回复"开始"。之后每做完一个任务，它会停下来汇报，你看完回复"继续"或提意见。

### 用 Codex 开工
同样在这个文件夹里启动 Codex，粘贴同一段话即可（Codex 会自动读 AGENTS.md）。

### 让 Codex 审查（推荐）
每当 Claude Code 完成一个任务，在 Codex 里粘贴：

```
你是本项目的审查员，不写新功能。请阅读 AGENTS.md 和 docs/02_P0_TASKS.md，
检查任务 Txx 的代码：①是否满足验收标准 ②测试是否真的通过 ③是否改了不该改的文件
④有没有明显 bug。用中文列出问题，按"必须修 / 建议修"分类。不要直接改代码。
```

把 `Txx` 换成刚完成的任务编号。

### 你需要亲自拍板的三个时刻
1. **T06 完成后（P0a 关卡）**：Agent 会给一份"1000 场模拟报告"，看阵容和战术是不是真的影响胜负。这关不过，后面不做。
2. **T10 完成后**：第一次看到像素小人打比赛，看好不好看。
3. **T11 完成后**：自己连玩 10 场，决定进不进入 P1。
